# 驾校招生助手（微信小程序 · 云开发版）

> 这是仓库 [jiaxiaohuoke](../README.md) 里的小程序版。网页版（Ubuntu / Docker 部署）的说明见仓库根目录的 README。

招生团队自己用的工作台：登记客户、排跟进时间、付款前四项核对、按节点做交付。
内容和措辞按《驾校业务视频完整文案》整理，和之前的网页版是同一套规则。

数据放在你自己小程序的**微信云开发**里，不需要服务器、域名和备案的网站。


## 里面有什么

| 底部页签 | 做什么 |
| --- | --- |
| 今日 | 今天要跟进谁、谁逾期了、谁没排期；哪些学员待办到期、7 天内要考试 |
| 客户 | 登记、分级（A/B/C/D）、记录跟进、付款前四项核对、收定金 / 正式报名 |
| 交付 | 正式报名后的学员：节点清单、资料、四科考试、拿证回访、异常台账 |
| 资料 | 产品卡、统一话术（能自动带上产品卡里核实过的内容）、获客渠道、转介绍、开始与红线 |
| 我的 | 跟进日历、数据看板、每日数据；管理员还有成员、团队设置、自检 |

几条写死在程序里的规矩：

- 还在跟进的客户必须有下次跟进时间；交付中的学员必须有下次动作日期。
- “已交定金”“已正式报名”只能在四项都核对过之后设；正式报名还要求已签合同、已开凭证。
- 异常要写清联系了谁、预计何时解决；解决后回访确认，才算关闭。
- 只登记业务必要的信息，看起来像身份证号的内容存不进去。
- 产品卡上没核实的项目一律显示“按当前合作协议核验”，话术不会替你编内容。


## 第一次部署（大约 10 分钟）

1. **导入项目**：微信开发者工具 → 项目 → 导入项目 → 选这个文件夹（仓库里的 `wechat-miniprogram/`）。AppID 用你自己的小程序
   （`project.config.json` 里的 `appid` 是作者的，导入时换成你自己的），后端服务选“微信云开发”。
   第一次打开会问“您信任此项目的作者吗”，选“信任并运行”。
2. **确认云环境**：左边文件列表里 `cloudfunctions` 那一行会写着“当前环境: ××”。只开通过一个环境就不用管；
   有多个环境时，右键 `cloudfunctions` 选要用的那个，并把环境 ID 填进 `miniprogram/config.js` 的 `ENV_ID`。
3. **改创建口令（必做）**：打开 `cloudfunctions/api/config.js`，把 `TEAM_CREATE_CODE` 从 `CHANGE-ME` 换成你自己的一串字符。
   开源仓库里的 `CHANGE-ME` 谁都看得到，不改就等于没有口令。
   小程序上线后任何人都能搜到，这个口令用来防止不相干的人在你的云环境里建团队。
4. **部署云函数**：右键 `cloudfunctions/api` → “创建并部署：云端安装依赖（不上传 node_modules）”，等一分钟左右。
   以后改了云函数的代码，同一个位置的菜单会变成“上传并部署：云端安装依赖”。
5. **创建团队**：模拟器里选“创建团队”，填团队名称、你的称呼和上面的口令。你就是管理员。
6. **跑一遍自检**：我的 → 自检 → 开始自检。它会在你的云环境里把登记、跟进、报名、交付、异常、统计和
   “团队之间互相看不到”真的走一遍（一共 9 步，十几秒），用的是带标记的临时团队，结束时全部删掉。全部通过就可以用了。

可选：把云函数的超时时间从默认的 3 秒改成 20 秒。位置在开发者工具工具栏的“云开发” → 云函数 → `api` 那一行的“版本与配置”
→ 配置 → 高级配置 → 执行超时。平时每次操作远用不到 3 秒，改大只是给网络抖动留余量。


## 上线之前（这几件事只能你自己在微信后台做）

- **服务类目**：个人主体选“工具”下面的类目。“驾校培训”类目要求企业主体和《机动车驾驶员培训备案》，个人主体选不了，也不需要选——
  这是团队内部的工作工具，不是面向学员的招生页面。
- **用户隐私保护指引**：小程序后台 → 设置 → 服务内容声明 → 用户隐私保护指引，声明使用“剪切板”。
  复制产品卡、话术和邀请码用到它；不声明的话，真机上点“复制”会失败（程序会提示原因，并让你长按手动复制）。
- **小程序备案**：2023 年 9 月以后新上线的小程序都要先备案，在小程序后台按提示做。
- **提交审核时**：在“审核备注”里写明这是团队内部使用的工具，并把创建口令告诉审核人员，例如：
  “首页选‘创建团队’，团队名称和称呼任意填写，创建口令填 ××××，创建后即可体验全部功能。”
- **费用**：云开发是按套餐收费的，以开发者工具“云开发”控制台里显示的为准。这个小程序只用到云函数和云数据库，用量很小。


## 团队怎么用

- **邀请同事**：我的 → 成员，把邀请码发给对方。对方在小程序里选“加入团队”，填邀请码和称呼，然后你在成员页点“通过”。
  邀请码泄露了可以“换一个”，已经加入的人不受影响。
- **两种角色**：管理员能看全部数据，能改产品卡、话术、渠道、团队设置和成员；成员做日常的登记、跟进、交付。
- **成员只看自己的**：团队设置里可以打开。打开后成员只看到自己负责的客户和学员（销售负责人仍然看得到自己签下的学员），
  管理员不受影响。
- **有人离开**：管理员在成员页把他“停用”，他马上进不来。他名下的客户和学员还在他名下，记得在客户页“编辑资料”里改给别人。
- **一个微信号只能在一个团队里**。想换团队要先在“我的”里退出；唯一的管理员不能退出，要先把别人设为管理员，或者在团队设置里解散团队。


## 数据在哪里，谁看得到

- 数据在云数据库的 10 个集合里，名字都以 `jx_` 开头（第一次使用时自动建好）。
- 小程序端**不直接读写数据库**，所有读写都经过云函数 `api`。云函数只认微信传给它的身份（openid），
  并且每次都按“这个人属于哪个团队、能看到哪些记录”来过滤。两个团队之间互相看不到，自检的第 8 步验证的就是这件事。
- 集合的权限保持默认的“仅创建者可读写”就好：记录都是云函数写的，小程序端读不到；云函数自己不受这个限制。
  想更严格可以改成“所有用户不可读写”，**不要**改成“所有用户可读”。位置：云开发 → 数据库 → 选集合 → 数据权限。
- 备份：云开发控制台 → 数据库 → 选集合 → 导出。小程序里没有做导出功能。
- 想从头再来：团队设置 → 解散团队，会删掉这个团队的全部数据。


## 和网页版的区别

- 这一版没做：周复盘、月度渠道对比和成本、对比清单、内容选题、转介绍奖励的发放记录、漏斗目标线、导出和备份。
- 多出来的：团队和邀请码（网页版是一个部署一个团队，这里一个云环境可以有多个互相隔离的团队）。
- 两边的数据不互通。


## 文件怎么组织的

```
miniprogram/            小程序端
  app.js app.json app.wxss
  config.js             云环境 ID、云函数名
  utils/api.js          调云函数的唯一入口
  utils/page.js         所有页面共用的做法：加载、提交、表单、跳转、复制
  tpl/                  几个页面共用的片段（客户行、学员行、报错条）
  pages/                25 个页面，每个页面一个文件夹
  images/               底部页签的图标（目前没有启用，见下面的说明）
cloudfunctions/api/     云函数（只有这一个）
  index.js              入口
  config.js             创建口令、时区
  lib/store.js          读写数据库的唯一入口
  lib/ctx.js            调用的人是谁、在哪个团队、能看到什么
  lib/consts.js         固定内容：交付清单、产品卡字段、默认话术和渠道、红线
  lib/selftest.js       自检
  handlers/             各个功能：团队、客户、交付、资料、今日与数据
tests/                  本地测试（不需要云环境，用内存里的假数据库）
```

改了 `cloudfunctions` 里的东西要重新“上传并部署”；改了 `miniprogram` 里的东西，开发者工具会自动重新编译，发给用户则要重新“上传”并提交审核。


## 底部页签为什么只有文字

`miniprogram/images/` 里有一套页签图标，但 `app.json` 里目前没有引用它们：在开发者工具的模拟器里，这些图标第一次打开时正常，
重新编译之后变成了裂图（工具自己的本地服务对图标请求返回 403），原因没有查清。为了不让页签在任何环境下出现裂图，这一版先只用文字。
想启用图标，在 `app.json` 的 `tabBar.list` 每一项里加上 `"iconPath": "images/tab-today.png"`、`"selectedIconPath": "images/tab-today-on.png"`
（客户 customers、交付 students、资料 library、我的 me 同理），在模拟器和真机预览里都确认显示正常后再上传。


## 本地测试

需要 Node 18 或更新的版本，不需要安装任何依赖：

```
node --test tests/test_*.js
```

- `test_team / test_customers / test_delivery / test_library / test_overview / test_access / test_gaps`：直接调云函数，检查规则、权限和团队隔离。
- `test_ui`：在 Node 里把小程序页面“跑起来”，按界面上的文字去点、去输入，小程序端和云函数一起测。
- `test_static`：页面登记全不全、WXML 里绑定的函数存不存在、有没有调用云函数里没有的动作。
- `test_selftest`：自检本身。

这些测试用的是假的数据库和假的小程序运行环境，替代不了真机——真实环境的行为由“自检”和在开发者工具里的实际操作来确认。
`tests/mp/shots.js` 可以把每个页面在本地画出来截图（需要另装 playwright），只是开发时看排版用的。
